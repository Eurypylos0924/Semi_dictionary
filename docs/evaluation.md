# 평가 (evaluation)

> 담당 브랜치: `evaluation_branch` · 담당 파일: `src/evaluation/`, `tests/test_evaluation.py`
> 이 문서는 해당 영역의 PR에서만 수정한다 ([협업 방식](workflow.md)).

```bash
uv run python -m src.evaluation.retrieval_eval --save --tag 322docs                                   # 초록 기반 질문(questions.jsonl)
uv run python -m src.evaluation.retrieval_eval --questions src/evaluation/questions_field.jsonl --save --tag field-322docs   # 현업 표현 질문
uv run python -m src.evaluation.faithfulness --configs baseline,max_judge --sets field,original --save --tag compare    # 답변 근거 충실도
uv run python -m src.evaluation.ablation_rewrite    # 쿼리 재작성 비교 (docs/rag.md)
uv run python -m src.evaluation.ablation_judge      # 점수 게이트 vs LLM 판정 (docs/rag.md)
```

## 현업 표현 질문 세트 (`src/evaluation/questions_field.jsonl`, 2026-10-20)

기존 질문이 초록을 보고 쓴 쉬운 평가라서, 논문 말투가 아닌 "막힌 사람이 묻는 말투"의 질문 20개를 따로 만들었다.

**만든 과정**
1. Claude가 **초록을 열어 보지 않고** 도메인 지식만으로 후보 20개를 작성했다. 증상형("~했는데 왜?"), 모호한 질문, 어휘 비틀기(예: "Poole-Frenkel" 대신 "고전계 구간 기울기가 바뀐다")를 섞었다. 다만 앞서 코퍼스 제목들을 본 적이 있어 주제는 겹친다.
2. 사용자(박종원)가 초안 전체를 승인했다("이대로 해도 될 것 같다"). 문장 수정이나 본인 경험 질문 추가는 없었으므로 **질문의 현실성 검수는 승인 수준**이다.
3. 정답 논문은 검색기 결과가 아니라 **코퍼스를 키워드로 스캔해 후보를 뽑고 초록을 읽어 표시**했다(검색기에 맞춘 정답이 되는 것을 막기 위해). 답할 논문이 없으면 수집 빈틈으로 표시했다.

| 구분 | 개수 | 질문 |
| --- | ---: | --- |
| 답 있는 질문 | 14 | F01~F09, F11~F15 (정답 논문 2~5편, 상당수는 초록에 일부만 있는 "부분 답변"으로 `note`에 명시) |
| 수집 빈틈 (`coverage_gap`) | 3 | F10 CMP 후 Idsat 저하, F16 M2 높이와 RC, F17 Focus/ET 최적화 (코멘토 경험 영역, 코퍼스에 0건) |
| 범위 밖 (`out_of_scope`) | 3 | F18 GAA nanosheet, F19 EUV LER, F20 DRAM 리프레시 |

- F01("열처리했더니 누설이 늘었어, 결정화 때문이야?")은 코퍼스 근거가 **"결정화만으로는 누설이 크게 늘지 않았다"** 쪽이라 질문의 전제와 엇갈린다. 무조건 "네"로 답하면 실패인 시험 문항이다.

### 검색 결과 (임베딩만 사용, 코퍼스 322건)

| 질문 세트 | 질문 수 | Hit@1 | Hit@3 | Hit@5 | Recall@5 | MRR |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 초록 기반 (`questions.jsonl`) | 27 | 0.889 | 0.963 | 1.000 | 0.957 | 0.929 |
| **현업 표현 (`questions_field.jsonl`)** | 14 | **0.643** | 0.929 | 0.929 | **0.606** | **0.781** |

### 발견

1. **현업 표현에서 지표가 크게 떨어져 평가가 변별력을 갖게 됐다.** Hit@1 0.889 → 0.643, Recall@5 0.957 → 0.606. 상위 5위 안에서 정답을 못 찾은 질문은 F09(박막 XRD 피크가 안 보이면 비정질인가, 첫 정답이 10위)였다.
2. **점수 게이트 0.30이 현업 표현에서는 맞지 않는다.** 답 있는 질문 2개가 게이트에 막힌다(F11 dishing/erosion 0.194, F15 lot 수율 급락 0.207). 반면 답 없는 질문의 1위 점수는 0.14~0.26이어서, 답 있는 질문(0.19~0.21)과 구간이 겹쳐 **임계값 하나로는 분리할 수 없다.**
   0.30은 초록 표현 질문(답 있는 질문의 최소 0.387)으로 정한 값이라 현업 표현에는 편향되어 있다. 이 세트에 맞춰 낮추면 평가 세트에 맞추는 튜닝이 되므로 지금은 바꾸지 않는다. 재정렬 점수나 LLM 판단 같은 **다른 신호**가 필요하다.
3. 수집 빈틈 3개와 범위 밖 3개는 모두 게이트가 차단했다(점수 0.14~0.26). 의도한 거절이지만 위 2번 때문에 안심할 수는 없다.

### 한계

- 정답 표시를 Claude 한 명이 했고 사용자가 검증하지 않았다. **정답 누락이 있을 수 있고**, 이 경우 검색이 다른 관련 논문을 찾아도 miss로 계산되어 Recall이 낮게 나온다(Recall 0.606의 일부는 이 때문일 수 있음).
- 답 있는 질문이 14개뿐이라 질문 하나가 지표 약 7%p를 좌우한다. 큰 차이만 의미가 있다.
- 질문 작성과 정답 표시를 같은 Claude가 해서 코퍼스 맥락의 영향을 완전히 배제하지 못한다.
- 검색 지표만 쟀다. **답변의 근거 충실도는 아직 측정하지 않았다.**

## 점수 게이트 신호 실험 (`src/evaluation/gate_signals.py`, 2026-10-20)

현업 표현 질문에서 점수 게이트(검색 1위 점수 < 0.30이면 거절)가 답 있는 질문을 막는 문제를 풀기 위해, **점수 하나 대신 상대 신호가 더 잘 가르는지** 실험했다. LLM 호출 없이 검색 점수만 사용한다. 두 질문 세트를 합쳐 답 있는 질문 41개, 답 없는 질문 9개로 비교했다.

```bash
uv run python -m src.evaluation.gate_signals --save   # 결과: results/gate_signals_<날짜>.md
```

| 신호 | AUC 초록 기반 | AUC 현업 표현 | AUC 합친 값 |
| --- | ---: | ---: | ---: |
| top1 (현재 게이트) | 1.000 | 0.940 | 0.970 |
| 상위5 평균 | 1.000 | 0.929 | 0.970 |
| 1위-5위 차이 | 0.914 | 0.810 | 0.867 |
| 1위-2위 차이 | 0.802 | 0.702 | 0.794 |
| z(1위) (코퍼스 전체 분포 대비) | 0.605 | 0.524 | 0.623 |
| z(상위5 평균) | 0.691 | 0.512 | 0.602 |

AUC는 "답 있는 질문의 신호가 답 없는 질문보다 클 확률"이다(1.0 완벽, 0.5 무작위).

### 결론

1. **상대 신호(1위-2위 차이, 1위-5위 차이, z 점수)는 배제한다.** 모두 top1보다 분리력이 낮고(AUC 0.60~0.87 vs 0.97), 한 세트에서 정한 임계값이 다른 세트에서 통하지 않는다(교차 검증에서 답 있는 질문을 100% 거절하거나 답 없는 질문을 100% 통과). 코퍼스 전체 점수의 평균·표준편차는 질문이 아니라 코퍼스 특성이라 거의 정보가 없었다.
2. **top1과 상위5 평균은 분리력이 높다(합친 AUC 0.97). 문제는 신호가 아니라 임계값이 아니다.** 현업 표현 세트에서 최적 임계값(Youden J)이 0.298로, 현재 0.30은 이미 거의 최선의 절충이다. 현재 게이트는 답 있는 질문의 14%(F11, F15)를 거절하고 답 없는 질문은 0% 통과시켜 **보수적**으로 동작한다.
3. **임계값을 낮춰도 해결되지 않는다.** F11(0.194), F15(0.207)가 답 없는 질문 일부(F18 0.255, F20 0.248, F10 0.206)보다 점수가 낮아 구간이 겹친다. 0.19 근처로 낮추면 답 없는 질문 6개 중 3개가 LLM까지 넘어간다.
4. 따라서 풀려면 **그 질문들의 점수 자체를 올리거나**(현업 말투를 논문 말투로 바꿔 검색: 쿼리 재작성), **점수 외 증거**(LLM 판정, 재정렬기)를 써야 한다. 점수만으로 더 잘 가르는 방법은 이 실험에서 찾지 못했다.

### 한계

- 답 없는 질문이 초록 기반 3개, 현업 표현 6개뿐이라 AUC와 교차 검증 임계값이 불안정하다. 질문 하나가 바뀌면 크게 달라질 수 있다.
- 신호를 고르고 평가하는 데 같은 질문을 써서 약한 과적합이 있다.
- "답 있음/없음" 라벨도 Claude가 정했고 사용자가 검증하지 않았다.

## 답변 근거 충실도 (`src/evaluation/faithfulness.py`, 2026-10-20)

지금까지 검색 지표와 게이트만 쟀고 **최종 답변이 근거에 충실한지는 재지 않았다.** 인용 번호가 맞아도 내용이 부풀려지는 문제를 처음으로 수치로 확인했다.

**측정 방법**
1. 답이 있는 평가 질문(현업 표현 14 + 초록 기반 27)마다 파이프라인으로 답변을 만든다(설정별: `baseline` = 원문 검색 + 점수 게이트, `max_judge` = `max` 검색 + LLM 판정 게이트).
2. **채점 LLM이 답변을 사실 주장 단위로 쪼개** 참고 논문 초록과 대조해 4가지로 판정한다: `supported`(인용한 논문이 뒷받침) · `misattributed`(내용은 다른 논문에 있는데 번호를 잘못 붙임) · `unsupported`(어떤 초록에도 없음) · `contradicted`(반대).
3. 정답에 들어가야 할 핵심 내용(`expected_points`)을 얼마나 담았는지(완결성)를 따로 채점한다.
4. 채점이 맞는지 사람이 확인할 **검수용 표본**(무작위 주장 12개, `results/faithfulness_spotcheck_*.md`)을 함께 만든다.

답변은 Gemini flash-lite가 만들고, 채점은 **다른 제공자인 NVIDIA `nemotron-3-super-120b`** 가 한다(같은 모델이 자기 답변을 채점하는 편향을 줄이기 위해). 처음에는 더 강한 `gemini-3.5-flash`로 채점하려 했으나 **무료 등급의 일일 한도(모델당 하루 20회)** 에 걸려 바꿨다.

### 결과

| 설정 | 세트 | 질문 | 답변/거절 | 주장 수 | 충실도 | 번호만 틀림 | 근거 없음·반대 | 완결성(답변한 질문) | 완결성(전체) |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| baseline | 현업 표현 | 14 | 9 / **5** | 34 | 88.2% | 0.0% | 11.8% | 48.4% | 31.1% |
| max_judge | 현업 표현 | 14 | 12 / **2** | 46 | 87.0% | 0.0% | 13.0% | 47.2% | 40.4% |
| baseline | 초록 기반 | 27 | 27 / 0 | 110 | 96.4% | 0.0% | 3.6% | 75.0% | 75.0% |
| max_judge | 초록 기반 | 27 | 27 / 0 | 115 | 99.1% | 0.0% | 0.9% | 77.6% | 77.6% |

채점이 주장으로 뽑은 "논문에서 확인되지 않음" 같은 **한계 표시 문장**(정직한 표시인데 오판되는 경우)을 제외하면(결과를 본 뒤의 보정이라 제외 전 수치와 함께 적는다): 현업 표현 충실도 baseline 90.6%, max_judge 95.2%. 나머지 세트는 변화 없음.

### 발견

1. **답변은 대체로 근거에 충실하다.** 충실도 87~99%, **번호만 틀린 경우는 0건**(주장 305개). 이 답변 모델에서는 인용 번호를 믿을 수 있다(로컬 소형 모델에서 보였던 "번호는 맞는데 내용은 다른 논문" 문제는 나타나지 않음).
2. **진짜 환각이 1건(두 설정 모두 같은 질문에서) 확인됐다.** Q04 "펄스 시간은 0.5초 이상을 적용해야 합니다"는 근거 초록에 **숫자가 없다**(`pulse times of must be applied`). OpenAlex 초록에서 수식·수치가 빠졌고 모델이 그 빈자리를 지어냈다. **데이터 품질이 환각을 부른 사례**로, 수식 누락 초록을 탐지·제외하는 것이 collector/preprocessing 후속 과제다.
3. **가장 큰 문제는 환각이 아니라 거절이다.** 현업 표현 질문 14개 중 baseline은 **5개(36%)를 거절**했다. 점수 게이트가 막은 것은 2개(F11, F15)뿐이고, 나머지 3개(F09, F13, F14)는 게이트를 통과한 뒤 **답변 LLM이 스스로 "근거를 찾지 못했습니다"라고 거절**했다(부분 답변이면 확인되는 부분을 답하라는 프롬프트 규칙보다 "답할 수 없으면 거절" 규칙을 따름). 게이트만 재서는 보이지 않던 거절이다.
4. **`max` 검색 + LLM 판정은 거절을 줄이면서 충실도를 해치지 않았다.** 현업 표현에서 거절 5/14 → 2/14(F14, F15는 판정이 거절), 완결성(거절을 0점으로 계산한 전체 기준) 31.1% → 40.4%. 충실도는 87.0% vs 88.2%(제외 후 95.2% vs 90.6%)로 채점 노이즈 안이다. 쉬운 질문 세트에서도 해롭지 않았다(99.1% vs 96.4%, 완결성 77.6% vs 75.0%). 비용은 질문당 LLM 호출 2회 추가(재작성, 판정)다.
5. **완결성이 낮다.** 답변한 현업 표현 질문에서 핵심 내용의 약 절반(47~48%)만 담았다. 상위 5개 검색 결과에 정답 논문이 일부만 들어오는 한계(검색 Recall@5 약 0.6)에 묶여 있어, 답변 생성보다 검색 개선이 필요하다.

### 채점 결과를 어떻게 믿을 수 있나 (직접 확인한 내용)

채점도 LLM이라 틀린다. 문제로 표시된 주장 15개(중복 포함)를 근거 초록과 대조해 보았다(Claude의 확인이며 독립 검증이 아니다).

| 구분 | 개수 | 예 |
| --- | ---: | --- |
| **진짜 문제** | 2 | Q04 숫자 지어내기(두 설정에서 같은 주장) |
| **채점기 오탐** | 6 | 답변이 "논문에서 확인되지 않음"이라고 한계를 밝힌 문장을 `unsupported`/`contradicted`로 판정(F03, F06, F07, F13), 제목에 "suppression"이 있는데 초록만 보고 `unsupported`로 판정(Q06) |
| 경계(일반 상식·추론) | 7 | 패드 컨디셔닝의 목적처럼 초록에 직접 없지만 통상적인 설명(F12 등), 출처 없는 총평(F05) |

- **두 채점기 비교**: 같은 현업 표현 답변 7개를 Gemini 3.5 flash와 NVIDIA 채점기가 모두 채점한 결과, **충실도가 4개에서 다르게 나왔다**(예: F12 0% 대 75%, F07 100% 대 60%). 주장을 쪼개는 단위가 달라 분모부터 다르고 방향도 일정하지 않다. 완결성은 비교적 일치했다(대부분 ±17%p 이내). 따라서 **충실도 수치의 차이는 약 ±10~15%p 미만이면 의미가 없다.**
- 채점 출력 형식 오류로 채점하지 못한 답변이 1건 있어 집계에서 빠졌다(재시도 후에도 JSON이 깨짐).

### 한계

- 채점자가 LLM이다. **검수용 표본 12개를 사람이 확인하지 않았다**(`results/faithfulness_spotcheck_2026-10-20_compare.md`에 체크란이 있다).
- 현업 표현 질문이 14개라 질문 하나가 설정 간 차이를 크게 흔든다.
- 답변 모델은 Gemini flash-lite 하나만 비교했다. 더 강한 모델과의 비교는 무료 등급 한도로 하지 못했다.
- 질문당 답변을 한 번만 생성했다(온도 0). 한계 표시 문장 제외는 결과를 본 뒤의 보정이다.
- `expected_points`는 정답 논문 초록에서 뽑았기 때문에, 부분 답변 질문에서는 완결성의 이론적 상한이 100%보다 낮다.

### 확인된 것 / 말할 수 없는 것

1. **Q04의 "0.5초 이상"은 두 설정 모두에서 사라졌다.** 답변은 펄스 포화와 표면 수산화라는 정성적 내용만 쓰고 "초록 내 수치가 누락되어 구체적인 펄스 시간 값은 확인할 수 없다"고 밝힌다. 새 답변 캐시에서 "0.5초"가 든 답변은 0건이다.
2. **이것이 채점기를 바꾼 효과가 아님을 확인했다.** 새 채점기(ultra)에 옛 환각 답변 2개(baseline·max_judge)를 다시 채점시키니 둘 다 `unsupported`("초록에 구체적인 펄스 시간 수치가 누락되어 확인 불가")로 잡았다. 즉 새 채점기는 이 환각을 놓치지 않고, 새 답변에는 그 주장이 없다.
3. **전체 충실도 수치가 올랐다고 프롬프트 덕이라고 말할 수는 없다.** 채점 모델·코퍼스·프롬프트가 동시에 바뀌었고 이전 채점기 대비 편차도 있었다(2026-10-20의 두 채점기 비교에서 같은 답변도 충실도가 크게 달랐다). 특히 현업 표현 max_judge 87.0% → 98.0%는 질문이 14개뿐인 세트에서 채점기 교체와 섞여 있어 해석하지 않는다. 같은 채점기로 옛 답변을 전부 다시 채점하지 않았다.
4. **가장 큰 문제는 여전히 거절이다.** baseline은 현업 표현 14개 중 5개를 거절한다(변화 없음). 완결성도 거의 그대로이고(전체 34.7% / 38.3%), 검색이 정답 논문을 일부만 가져오는 한계가 남아 있다.
5. 남은 `unsupported`/`misattributed` 주장(현업 표현 4건, 초록 기반 2건)은 주로 일반 상식에 가까운 설명이다. 예: 패드 컨디셔닝의 목적(F12), 섬 성장으로 얇게 측정(F03), θ는 2θ의 절반(Q23), 고전계 PF 방출을 논문 4편 인용에 1편만 다름(Q26). 새로 생긴 수치 환각은 보이지 않지만 **내가 이 주장들을 초록과 일일이 대조하지는 않았다.**

### 한계

- 검수용 표본은 두 벌이다. 2026-10-20 표본(12개)은 사용자가 **5개를 확인해 모두 "판정이 맞다"**고 표시했다(7개 미확인; 5개로는 채점기 정확도를 말하기 어렵다). 이번 표본 12개(`results/faithfulness_spotcheck_2026-10-22_after-mathloss.md`)는 아직 아무도 확인하지 않았다.
- `math_loss` 표시 논문이 1건뿐이라 규칙 10의 효과는 사실상 Q04 한 질문으로만 확인했다. 질문당 답변을 한 번만 생성했다(온도 0).
- 표시되지 않은 수식 누락(정제 규칙이 못 잡은 것)에는 이 처리가 작동하지 않는다.

## 근거 논문 수(k) 실험: k를 늘리면 거절·완결성이 나아지나 (2026-10-26)

**가설**: 검색 Recall은 k를 늘리면 오른다(현업 표현 14개, original 기준 Recall@5 0.61 → @10 0.75, `max`는 0.56 → 0.72). 근거로 넘기는 논문을 5개에서 8·10개로 늘리면 정답 논문이 더 많이 컨텍스트에 들어가 답변의 완결성이 오르고 거절이 줄 것이다.

**방법**: `max` 검색 + `judge` 게이트(`max_judge`)에서 k만 5 / 8 / 10으로 바꿔 충실도 평가를 돌렸다(`src/evaluation/faithfulness.py`의 설정 `max_judge_k8`, `max_judge_k10`). 답변 모델·채점기(`nemotron-3-ultra-550b-a55b`)·코퍼스(314건)·프롬프트는 같다.

| 설정 | 세트 | 답변/거절 | 충실도 | 번호만 틀림 | 근거 없음·반대 | 완결성(답변한 질문) | 완결성(전체) |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| k=5 | 현업 표현 | 12 / 2 | 98.0% | 0.0% | 2.0% | 44.7% | 38.3% |
| k=8 | 현업 표현 | 12 / 2 | 91.5% | 2.1% | 6.4% | 46.5% | 39.9% |
| k=10 | 현업 표현 | 13 / 1 | 92.2% | 5.9% | 2.0% | 43.8% | 40.7% |
| k=5 | 초록 기반 | 27 / 0 | 99.2% | 0.0% | 0.8% | 78.2% | 78.2% |
| k=8 | 초록 기반 | 27 / 0 | 96.2% | 1.5% | 2.3% | 72.1% | 72.1% |
| k=10 | 초록 기반 | 27 / 0 | 99.3% | 0.7% | 0.0% | 72.7% | 72.7% |

### 결과 해석

1. **가설은 맞지 않았다. k를 늘려도 답변의 완결성이 오르지 않았다.** 현업 표현에서 답변한 질문의 완결성은 44.7% → 46.5% → 43.8%로 제자리이고, 초록 기반은 오히려 78.2% → 72%대로 내려갔다. 검색은 정답 논문을 더 찾아오는데(Recall) 답변은 그것을 더 담지 않는다.
2. **충실도는 내려갔다.** 현업 표현에서 98.0% → 91.5%(k=8), 92.2%(k=10). 특히 **번호만 틀린 주장**이 0건에서 2.1%, 5.9%로 생겼다(예: F13에서 내용은 논문 [1], [8]에 있는데 [2]로 인용). 논문이 많아질수록 모델이 번호를 잘못 붙인다. 초록 기반은 k=10에서 다시 99.3%라 방향이 일정하지 않다.
3. **거절은 거의 그대로다.** 현업 표현 거절 2/14가 k=10에서 1/14가 됐을 뿐이고(질문 하나 차이), k=8은 같았다.
4. 질문이 14개(현업)·27개(초록 기반)이고 답변을 한 번만 생성했다. 차이 일부는 우연일 수 있다. 다만 **세 설정 모두에서 완결성이 오르지 않았다는 점**은 일관된다.

**결론: 기본 k는 5로 유지한다.** 이득이 없고 번호 오류 위험만 늘었다.

**이 결과가 가리키는 것 (검증은 하지 않았다)**: 완결성의 병목은 검색(Recall)이 아니라 **답변 생성 쪽**일 수 있다. 가능한 원인은 프롬프트의 "8문장 이내" 규칙(규칙 9)과 답변 모델이 컨텍스트의 일부만 쓰는 경향이다. 확인하려면 규칙 9를 바꾸거나 더 강한 모델로 같은 컨텍스트에서 비교해야 한다.

### 한계

- 같은 질문 세트로 여러 설정을 비교하고 있어(이전 실험 포함) 질문 세트에 맞춘 선택이 될 위험이 있다. 이번에는 k를 8, 10 두 값만 시험했고 결과를 보고 다른 값을 더 찾지 않았다.
- 채점은 LLM이고 사람이 확인하지 않았다(`results/faithfulness_spotcheck_2026-10-26_k-experiment.md`는 미확인).
