# 검색과 답변 생성 (rag)

> 담당 브랜치: `rag_branch` · 담당 파일: `src/rag/`, `tests/test_generator.py`, `tests/test_llm.py`
> 이 문서는 해당 영역의 PR에서만 수정한다 ([협업 방식](workflow.md)).

```bash
uv run python -m src.rag.retriever "CMP 공정에서 스크래치 결함이 생기는 메커니즘" -k 3   # 검색만
uv run python -m src.rag.ask "Cu CMP 공정에서 스크래치는 어떻게 줄일 수 있어?"            # 논문 근거 답변 + 출처
uv run python -m src.rag.ask "질문" --query-mode max                                         # 쿼리 재작성 검색 (original | rewrite | max)
uv run python -m src.rag.ask "질문" --gate-mode judge                                        # LLM 근거 판정 (score | judge)
```

## 검색 테스트 관찰 (2026-10-16, 질문 3개 수동 확인)

- CMP 스크래치 메커니즘, 웨이퍼맵 딥러닝 분류: 상위 3건이 모두 질문과 직접 관련된 논문이었다.
- "HfO2 박막에서 누설전류가 커지는 원인은?": 상위 3건이 증착 방법 논문이고, 누설전류 원인을 다룬 논문은 없었다.
  코퍼스에 HfO2 **누설전류 메커니즘** 논문이 부족한 것으로 보이며, 검색 모델보다 **수집 검색어의 문제**일 가능성이 크다.

## 답변 생성 (`src/rag/generator.py`)

```
질문 → 검색(상위 5) → [점수 게이트] → 프롬프트([1]~[5] 번호 붙인 초록) → LLM → 인용 번호 검증 → 답변 + 출처
```

환각을 두 겹으로 막는다. (팀 프로젝트 CodeClue에서 "근거 없이 답한 답변의 Faithfulness가 0"이었던 약점을 의식한 설계)

1. **점수 게이트**: 검색 1위 점수가 0.30 미만이면 LLM을 부르지 않고 "제공된 논문에서 근거를 찾지 못했습니다"로 답한다.
   평가 질문 기준 범위 밖 질문은 약 0.21, 답 있는 질문은 0.39 이상이었다. **잠정값이며 어려운 질문으로 재점검이 필요하다.**
2. **프롬프트 규칙 + 사후 검증**: 초록에 없는 내용 금지, 문장마다 `[n]` 인용, 질문과 논문의 조건(소재·공정)이 다르면 밝힐 것.
   답변이 인용한 번호가 실제 있는 논문인지 검사하고(`invalid_citations`), 인용이 하나도 없는 답변은 `uncited`로 표시한다. 출처는 **답변이 실제로 인용한 논문만** 보여준다.

### LLM 제공자 (`src/rag/llm.py`)

무료 서비스는 모델이 예고 없이 종료(EOL)되므로, 코드 수정 없이 환경변수로 갈아탈 수 있게 했다: `LLM_PROVIDER=gemini|nvidia|ollama`, `CHAT_MODEL=모델명`(생략하면 제공자 기본 모델).
CLI에서는 `uv run python -m src.rag.ask "질문" --provider ollama --model gemma3:4b`로 바꿔 쓸 수 있다.

| 제공자 | 기본 모델 | 같은 질문(Cu CMP 스크래치) 결과 |
| --- | --- | --- |
| **gemini** (기본) | `gemini-3.1-flash-lite` | **9초**. 인용한 [5]가 산화막 CMP 논문이라 질문 조건과 다르다고 스스로 밝힘. 초록에 없는 과장 없음 |
| gemini | `gemini-3.5-flash` | 36초, 품질은 비슷(조건 차이도 밝힘) |
| nvidia | `nvidia/nemotron-3-super-120b-a12b` | 약 47초. 앞서 기록한 과장 2곳 |
| ollama (로컬 CPU) | `gemma3:4b` | 91초. "근거를 찾지 못했다"고 말한 뒤 근거를 나열하는 모순. 핵심 근거 일부 누락 |
| ollama | `qwen2.5:7b` | 132초. **인용 번호는 유효하지만 내용을 다른 논문에 잘못 연결**(분사 방식을 [5]에 붙임), 용어 깨짐 |

- 질문 1개로 비교한 인상이므로 **모델 우열의 근거로는 약하다**. 근거 충실도(Faithfulness) 평가로 확인해야 한다.
- 로컬 모델은 비상용이다. 느리고 규칙 준수가 불안정하며, 인용 번호 검사만으로는 "번호는 맞는데 내용은 틀린" 경우를 못 잡는다.
- 모델 이름은 자주 바뀐다. 2026-10-16 확인: NVIDIA는 후보 18개 중 1개만 응답(나머지 EOL), Gemini는 2.5 계열이 종료되고 3.x 계열이 응답.
  Gemini 무료 등급의 한도는 출처마다 설명이 달라 [AI Studio](https://aistudio.google.com)에서 직접 확인해야 한다. 무료 등급에서는 입력이 모델 개선에 쓰일 수 있으므로 비공개 자료는 넣지 않는다.
- 필요한 키: `GOOGLE_API_KEY`(gemini), `nvidiaapi_key`(nvidia, 임베딩에도 사용), ollama는 키 불필요. `.env.example` 참고.

### 수동 확인 결과 (질문 4개, 초록과 대조)

| 질문 | 결과 | 평가 |

| EUV 펠리클 재료 | 점수 0.216 → LLM 호출 없이 "근거 없음" | 의도대로 동작 |
| CMP 후 Idsat 저하 원인 | 점수 0.226 → "근거 없음" | 코퍼스에 없는 내용이라 정직하게 거절. 현업 표현 질문에 답하려면 코퍼스 보강 필요 |
| SiC 게이트 산화막 신뢰성 | 점수 0.374로 게이트 통과, 4H-SiC MOS 논문 한 편을 근거로 답변 | 답은 초록에 근거하지만 ZrO2 적층 연구 한 편을 "SiC 소자 신뢰성 전반"으로 **일반화**함. 또한 이 질문은 코퍼스가 커지며 더 이상 범위 밖이 아님 |

- 시사점: **프롬프트만으로는 인용 번호가 맞아도 내용이 약간 부풀려지는 것을 막지 못한다.** 그래서 다음 단계에서 답변의 근거 충실도(Faithfulness)를 따로 측정해야 한다.
- 범위 밖 평가 질문은 코퍼스가 바뀌면 범위 안이 될 수 있다. 코퍼스를 바꿀 때마다 `U` 질문을 다시 확인한다.

## 쿼리 재작성 실험 (1단계, `src/rag/rewrite.py`, 2026-10-20)

현업 표현 질문은 논문 말투와 어휘가 달라 검색 점수가 낮아, 점수 게이트가 답 있는 질문을 막았다(평가 문서 참고). 질문을 논문이 쓰는 기술 용어의 영어 검색문으로 바꿔서 검색하면 나아지는지 측정했다.

| 방식 (`--query-mode` 또는 환경변수 `QUERY_MODE`) | 내용 |
| --- | --- |
| `original` (기본, 기존 동작) | 원문 질문만 검색 |
| `rewrite` | LLM(Gemini)이 만든 영어 검색문만 검색 |
| `max` | 원문과 재작성문을 모두 검색하고 **문서별 최고 코사인 점수**로 합침(RRF가 아니라 점수 게이트에 그대로 쓸 수 있음) |

재작성 예: `ALD로 올린 HfO2를 열처리했더니 누설이 늘었어. 결정화 때문이야?` → `leakage current increase in atomic layer deposition (ALD) HfO2 thin films after annealing and its correlation with crystallization`.
재작성 결과는 `data/cache/rewrites.jsonl`에 저장해 같은 질문은 LLM을 다시 부르지 않는다. 재작성 프롬프트에는 "범위 밖 질문을 코퍼스 주제로 억지로 끼워 맞추지 않는다"는 규칙을 넣었다(질문 의도 보존).

### 결과 해석

**좋아진 점**
- 게이트에 막혔던 두 질문이 풀렸다. F11 dishing/erosion 0.194 → 0.538, F15 lot 수율 급락 0.207 → 0.522. 답 있는 질문의 거절이 2/14 → 0/14.
- 현업 표현 세트의 Hit@1이 0.643 → 0.786(14개 중 2개 차이), MRR 0.781 → 0.814.
- 범위 밖 질문의 재작성은 질문 의도를 유지했다(예: `EUV 레지스트의 LER` → `line edge roughness (LER) reduction in extreme ultraviolet (EUV) photoresist`). 점수는 거의 오르지 않았다(F18 0.255→0.275, F19 0.183→0.237).

**나빠진 점**
- **Hit@3과 Recall@5가 현업 표현 세트에서 내려갔다**(0.929 → 0.786, 0.606 → 0.561). 질문별로 보면 첫 정답 순위는 5개에서 좋아졌지만, F02(Zr 도핑, 1위→5위)와 F04(얇은 HfO2 비정질, 1위→5위)는 크게 밀렸고 F03·F04·F14는 Recall@5가 내려갔다. 재작성이 질문을 한 갈래로 좁혀서 다른 정답 논문을 놓치는 것으로 보인다.
- **이미 논문 말투인 질문에서는 오히려 해롭다.** 초록 기반 세트 Hit@1 0.889 → 0.741(rewrite), 0.778(max).
- **답 없는 질문 하나가 게이트를 통과한다.** F10(CMP 후 Idsat 저하)이 0.206 → 0.388. 재작성문 `CMP induced drain current (Idsat) degradation`이 코퍼스에 많은 CMP 논문과 잘 맞는다. 코퍼스에 "CMP 논문"은 있지만 "CMP와 Idsat을 연결한 논문"은 없는 **부분 일치** 사례로, 점수로는 구분하기 어렵고 LLM 판정이 필요하다.
- 질문마다 LLM 호출이 1회 늘어난다(이번 실행에서 50건 재작성에 몇 분).

**임계값은 여전히 세트 사이에서 완전히 통하지 않는다.** 두 세트를 합치면 답 있는 질문의 최소(0.381, 초록 기반)가 답 없는 질문의 최대(0.388, F10)보다 살짝 낮아 겹침 없이 가르는 임계값이 없다(AUC 0.997). 한 세트에서 정해 다른 세트에 적용하면 재작성 점수에서는 초록 기반 → 현업 표현(임계값 0.337)에서 답 없는 질문 17%(F10)가 통과하고, 현업 표현 → 초록 기반(0.399)에서는 답 있는 질문 4%(1/27)가 거절된다. 원문 점수는 14% 거절 / 0% 통과였다(원문 점수 대 재작성 점수는 거절을 통과로 맞바꾼 셈에 가깝다).

`max`는 이번 측정에서 `rewrite`와 거의 같았고(현업 표현 세트는 재작성 점수가 거의 항상 더 높아 동일), 초록 기반 세트에서는 `rewrite`보다 덜 나빴다.

### 결론

- **쿼리 재작성은 순수한 이득이 아니다.** 게이트의 거짓 거절을 없앴지만 Recall을 낮추고, 부분 일치하는 범위 밖 질문 하나를 통과시켰다. 어떤 방식도 모든 지표에서 우세하지 않다.
- 그래서 기본값은 `original`로 두고 옵션으로만 제공한다. 사용자가 실제로 쓸 질문이 현업 표현이라면 `max`가 합리적인 후보다(원문 질문을 함께 검색해 이미 논문 말투인 질문의 손해를 줄임).
- 남은 문제(부분 일치, 임계값)는 점수가 아니라 **LLM이 근거의 적합성을 판정**해야 풀릴 가능성이 크다. 다음 단계의 후보다.

### 한계

- 질문이 적다(현업 표현 답 있음 14개, 답 없음 6개). 질문 하나가 Hit@1을 약 7%p 움직이므로 작은 차이는 의미가 없고, 위 차이 중 일부는 우연일 수 있다.
- 재작성 프롬프트는 한 번만 작성해 측정했고 지표를 보고 고치지 않았다(과적합 방지). 다른 프롬프트나 다른 LLM에서는 결과가 달라질 수 있다.
- 평가 질문과 정답 표시는 모두 Claude가 만들었고, 같은 질문이 설계 결정과 측정에 모두 쓰였다.
- 멀티 쿼리(검색어 여러 개)는 이 단계에 포함하지 않았다.

## LLM 근거 판정 (`src/rag/judge.py`, 2026-10-20)

점수 게이트는 "주제어가 겹치지만 질문이 묻는 관계는 없는" 경우를 가르지 못하고 임계값이 세트 사이에서 통하지 않았다(쿼리 재작성 실험 참고). 그래서 점수는 **하한선(0.15)** 으로만 쓰고, 그 위는 LLM이 검색된 초록을 읽고 판정한다. 환경변수 `GATE_MODE` 또는 `ask --gate-mode`로 켠다(기본은 기존 `score`).

```
검색(상위 5) → 1위 점수 < 0.15? → "근거 없음"(LLM 호출 없음)
            → LLM 판정: answerable | partial | none + 쓸 수 있는 논문 번호 + 이유
               none → 이유와 함께 "근거를 찾지 못했습니다" / answerable·partial → 답변 생성(partial이면 "확인되는 부분만 답하라"는 메모 추가)
               판정 형식 오류 → 기존 점수 게이트(0.30)로 대체
```

- 판정 결과는 `data/cache/judgements.jsonl`에 캐시한다(질문+논문 목록이 같으면 재사용).
- 판정이 고른 논문만 근거로 쓰는 옵션(`use_judge_selection`)은 **기본 꺼짐**이다(아래 발견 4).

### 측정 (현업 표현 질문: 답 있음 14, 답 없음 6 / 초록 기반: 답 있음 27, 답 없음 3)

| 게이트 | 검색 | 답 있는 질문 거절 | 답 없는 질문 통과 |
| --- | --- | --- | --- |
| 점수 0.30 (기존) | original | 2/14 (F11, F15) | 0/6 |
| 점수 0.30 | max | 0/14 | **1/6** (F10 CMP 후 Idsat) |
| LLM 판정 v1 | original | 3/14 (F13, F14, F15) | 0/6 |
| LLM 판정 v1 | max | 2/14 (F14, F15) | 0/6 |
| LLM 판정 v2 | original | 4/14 (F02, F13, F14, F15) | 0/6 |
| LLM 판정 v2 | max | **2/14** (F14, F15) | **0/6** |

초록 기반 세트는 모든 방식에서 0/27 거절, 0/3 통과였다(구분력이 없는 쉬운 세트). 판정 분포(v2, `max`, 현업 표현): 답 있는 질문 answerable 5 · partial 7 · none 2, 답 없는 질문 none 6.

### 발견

1. **이번 측정에서는 개수상 이득이 없다.** 판정+`max`(2/14, 0/6)는 기존 점수 게이트+`original`(2/14, 0/6)과 같은 개수다. 막히는 질문만 다르다(점수: F11·F15, 판정: F14·F15).
2. **그래도 `max` 검색을 쓰려면 판정이 필요하다.** `max`는 답 있는 질문의 거절을 0/14로 없앴지만 점수 게이트로는 부분 일치하는 범위 밖 질문(F10)을 통과시켰다. 판정은 이를 막았다(0/6). "검색은 `max`, 게이트는 `judge`"가 지금까지 측정한 조합 중 두 오류를 모두 낮게 유지한 유일한 조합이다.
3. **판정은 F14(링 패턴 → 어떤 공정)와 F15(수율 급락 원인을 좁히는 순서)를 일관되게 거절한다.** 사유는 "방법론은 다루지만 질문이 묻는 구체적 원인 대응·절차는 없다". 이 둘은 평가 질문의 정답 표시 메모에서도 '부분 답변, 특정 공정을 단정하면 환각'이라고 적었다. 즉 **판정이 틀렸다기보다 정답 라벨(답 있음/없음 이분법)이 모호하다.** 전체/부분/없음 3단계로 사람이 라벨을 다시 검수해야 판정을 제대로 평가할 수 있다.
4. **판정이 고른 논문만 쓰면 근거를 버린다.** 상위 5개 안에 있는 정답 논문 중 판정이 선택한 비율은 현업 표현에서 52%(`original`)·65%(`max`)였다. F01은 정답 3편 중 1편만 골라 "결정화만으로는 누설이 늘지 않았다"는 반대 근거를 놓친다. 선택이 답변 품질을 올린다는 증거가 없어 기본은 끈다.
5. 판정 출력 형식 오류가 2건 나왔다(`"relevant": [[1, 2]]`처럼 목록을 한 겹 더 감쌈). 중첩 목록·문자열 숫자도 읽도록 고쳤고, 그래도 실패하면 점수 게이트로 대체한다.

### 결과 해석 시 주의 (측정 과정의 문제)

- **v1 프롬프트의 "CMP와 Idsat" 예시는 평가 질문 F10에서 따온 것이다.** 따라서 v1에서 F10이 거절된 것은 독립적인 검증이 아니다. v2에서 일반화한 예시(`A 공정이 C 특성에 미치는 영향`)로 바꿨고 F10은 v2에서도 거절됐지만, 이 수정 자체가 결과를 본 뒤에 이루어졌다.
- v2는 v1 결과를 본 뒤 한 번만 수정했다(partial/none 경계 명확화). 개선이 없었고 오히려 거절이 늘었으며(3/14 → 4/14, `original`), 같은 평가 질문에 맞춰 계속 고치면 과적합이라 더 고치지 않았다.
- 판정 LLM이 답변 LLM과 같은 모델(Gemini flash-lite)이라 자기 선호가 있을 수 있다.

### 한계

- 현업 표현 질문 14개·답 없음 6개로 질문 하나가 7~17%p를 움직인다. 위 차이는 우연일 수 있다.
- 정답 표시와 질문을 Claude가 만들었고 사용자가 판정 결과를 검증하지 않았다.
- 판정 호출로 질문당 LLM 호출이 1회 늘어난다. 최종 답변의 품질(근거 충실도)은 이번에 측정하지 않았다.
